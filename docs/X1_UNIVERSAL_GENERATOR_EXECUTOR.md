# Digital Dominance Universal Generator: authoritative compiler and agent executor

**Status:** Development-branch implementation only, not autonomous production execution.

## One authoritative engine, not another platform

The X1 Universal Generator compiles build packets. GOD MODE Commander coordinates them; GOD MODE Lead Asset Foresight supplies cited market research and explicitly labeled simulations. The existing X1 control plane retains sole ownership of tenant and actor authorization, queue, leases, retries and receipts. Existing Railway worker x1-swarm-preview-1 remains the execution infrastructure. GitHub owns branches; Vercel creates previews; Supabase stores tenant-scoped evidence; Guardian validates independently; Base44 remains a transitional donor.

The catalog contains 35 generator families and 700 taxonomy types across 4,000 industry ideas. These are documented candidate capabilities, not 700 proven running agent services.

## Run the free preflight

On the authorized feature branch with Node 22+:

    node scripts/x1-universal-executor.mjs --preflight
    node scripts/x1-universal-executor.mjs --compile
    node --test tests/x1-universal-executor.test.mjs

These do not invoke models, enqueue jobs, create services or deploy.

## Activation requirements

1. Reuse the existing X1 preview worker. Its last observed allowed action classes contained only READ_ONLY; the deployed handler currently does not execute Codex coding jobs. Wire a narrow reviewed adapter into its existing dispatcher, and require a fresh scoped approval before any registry permission change.
2. Place a clean checkout of feature/dd-launch-wizard-build-20261014 in an independently verified isolated development workspace. Do not give the model process GitHub push or provider admin tokens. Preserve the original premium homepage screenshot SHA-256 stored in the manifest.
3. Bind an authenticated Codex CLI or equivalent model runner. Official installation reference: npm install -g @openai/codex. Non-interactive usage supports codex exec --sandbox workspace-write --ask-for-approval never, but the CLI sandbox does not replace OS isolation.
4. The current X1 control plane must issue a signed time-limited grant bound to exact task, source/manifest SHA, actor, tenant, worker, lease, branch and budget. This adapter expects Ed25519; the **issuer is not yet integrated**. Reuse or extend existing X1 HMAC authorization instead of creating another authority.
5. Verify and record a provider-enforced hard cost cap before any paid model calls. Default is **$0 of unapproved model spend**. Timeout and prompt instructions alone do not impose a monetary cap.
6. After coding, run actual build/type/lint tests, two-tenant auth and RLS negative tests, desktop/tablet/mobile screenshot checks, noindex and navigation, and independent Guardian validation. Only the separately authorized outer X1 worker may commit/push to this branch and request a Vercel preview. Production requires a separate scoped approval.

The adapter does not install credentials, create a worker, or start continuous execution merely by being committed.
